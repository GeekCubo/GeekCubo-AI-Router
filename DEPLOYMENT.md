# Deploying GeekCubo on a VPS

Target: an Ubuntu VPS running Docker Compose behind Nginx. GeekCubo runs
entirely on your own server under **your own** domain or hostname; it never
needs, contacts or redirects to a GeekCubo-operated service for installation,
dashboard access, inference or Local AI Connect.

The examples use reserved documentation names. Replace them with your own:

| Example | When it applies |
|---|---|
| `https://example.com` | A public HTTPS installation on a root domain (used throughout this guide). |
| `https://api.example.com` | The same installation on a subdomain instead. Root domain and subdomain are interchangeable choices; nothing in GeekCubo requires either. |
| `http://127.0.0.1:8787` | The local Docker installation (the Compose default). |
| `http://203.0.113.10:8787` | Direct IP access. Only for testing on a trusted network: it is plain HTTP, so the administrator password and API keys travel unencrypted. Prefer an SSH tunnel or HTTPS. |

The steps below are a procedure to follow on your own server; adapt hostnames,
paths and firewall rules to your environment. `./install.sh` automates most of
them (modes 1–5); this guide explains what it does and how to do it by hand.

---

## 0. Prerequisites

- Docker Engine 24+ with the Compose v2 plugin (`docker compose version`).
- A DNS A/AAAA record for your domain (e.g. `example.com` or `api.example.com`) pointing at the VPS.
- A TLS certificate **that covers that exact hostname**.
- ~1 GB RAM and 2 GB disk free. No GPU: GeekCubo itself only talks to remote APIs (local models run on separate hosts through Local AI Connect).

> **Certificate check (do this first).** A certificate issued for
> `example.com` does **not** cover `api.example.com` (or the other way round)
> unless it lists both names or is a wildcard. Verify the name you will use
> before cutting over:
>
> ```bash
> echo | openssl s_client -servername example.com -connect example.com:443 2>/dev/null \
>   | openssl x509 -noout -ext subjectAltName
> ```
>
> If your hostname is missing, issue a certificate for it
> (`certbot --nginx -d example.com`) before enabling the site.

## 1. Get the code and configure

```bash
git clone https://github.com/GeekCubo/GeekCubo-AI-Router.git geekcubo
cd geekcubo
cp .env.example .env
```

Edit `.env`. The values that matter in production:

| Variable | Why |
|---|---|
| `CREDENTIAL_ENCRYPTION_KEY` | Encrypts provider keys at rest. With SQLite it is generated automatically on first start and saved in `/data/.geekcubo-secrets`; set it yourself only on Postgres or to supply your own value (`openssl rand -hex 32`). Either way, **back it up**: losing it means stored provider keys cannot be decrypted. |
| `ALLOW_INSECURE_DEV_KEY` | Must be **unset/false** in production. |
| `TRUST_PROXY_HEADERS` | `true` behind Nginx, so session cookies are marked `Secure`. |
| `PUBLIC_BASE_URL` | Optional display URL for `./install.sh`: your own address, for example `https://example.com` or `https://api.example.com`. It does not configure DNS or the bind address. |
| `CUSTOM_PROVIDER_ALLOWED_LOCAL_HOSTS` | Leave empty unless you really run a local model server. |
| `REDIS_URL` | Optional. Moves the prompt cache to Redis. It does not make multi-worker deployment supported; GeekCubo runs as one process. |
| `LOCAL_CONNECT_PUBLIC_URL` | Your public HTTPS origin (for example `https://example.com`), written into the Local AI Connect install command; see below. |
| `SEARXNG_SECRET` | Optional. Generated by `./install.sh` when the `search` profile is chosen; used by the bundled SearXNG container. |

Never commit `.env`. `.gitignore` already excludes it.

## 2. Start the service

Recommended:

```bash
./install.sh
```

The installer creates `.env` only if it is missing, validates the Compose
configuration, builds and starts the service, waits for the real `/health`
endpoint, and prints the dashboard URL plus the one-time administrator setup
token on a fresh install. Rerunning it preserves the data volume, `.env`,
administrator, provider credentials, encryption secrets and API keys.

Equivalent manual commands (same Compose configuration):

```bash
docker compose up -d --build
```

Look for `geekcubo_starting` then `geekcubo_ready` in the logs. Health:

```bash
curl -fsS http://127.0.0.1:8787/health
```

The container binds to `127.0.0.1:8787` only; Nginx is the public face. If you
need the port elsewhere, change the `ports:` mapping in `docker-compose.yml`.

### Optional: native-Chat web search

Web search is off by default and never required. `./install.sh` offers to
configure it; the same choices can be applied later:

```bash
# Private SearXNG container on the internal network (no public port)
docker compose --profile search up -d
docker compose --profile search down      # stop it
```

With the `search` profile the SearXNG service is reachable only as
`http://searxng:8080/` from the api container. Point **Settings → Chat → Web
search** at that URL, choose mode `manual`, and use **Test connection** to
confirm. The installer writes `SEARXNG_SECRET` to `.env` the first time.

Brave and Tavily need no container: paste the provider's API key in the same
dashboard panel. Search-provider keys are stored encrypted, separately from
inference provider keys, and are never shown again. The SearXNG image is
pinned in `docker-compose.yml`; memory is capped at 512 MB. A failing SearXNG
health check never stops the api service — search simply reports its error.

### Native-Chat attachments and the data volume

Chat attachments are enabled by default. Uploaded bytes are written under an
opaque UUID name in `ATTACHMENT_DIR`, which defaults to an `attachments/`
folder next to the SQLite file — in the Compose setup that is
`/data/attachments`, so it is already inside the `geekcubo-data` volume and is
captured by the backup steps in §5. On Postgres the default is `./attachments`
relative to the working directory; set `ATTACHMENT_DIR` explicitly if that
directory is not on a persistent mount.

```bash
# Optional overrides in .env
ATTACHMENTS_ENABLED=true
ATTACHMENT_MAX_MB=25          # per file, clamped to the hard ceiling
ATTACHMENT_DIR=/data/attachments
```

Database rows live in `chat_attachments` / `chat_messages.attachments_json`;
the columns are created on startup by the same migration runner as the rest of
the schema. Deleting files from `ATTACHMENT_DIR` by hand leaves rows that
return `410 Gone` — treat the directory as part of the database, not as a cache.

Video attachments are probed and sampled with `ffmpeg`/`ffprobe`. The Docker
image does **not** bundle them (the runtime image stays small), so video uploads
still succeed but the model is told the file cannot be read. If you want video
frames, build an image that installs them on top of the one Compose builds
(tagged `geekcubo`):

```dockerfile
FROM geekcubo
USER root
RUN apt-get update && apt-get install -y --no-install-recommends ffmpeg \
    && rm -rf /var/lib/apt/lists/*
USER geekcubo
```

Audio is intentionally metadata-only: automatic speech transcription is not
enabled, and the model is never told it heard something it did not.


### Local AI Connect

Local AI Connect lets the gateway route to models on your own machines. The
model host runs `geekcubo-connector`, which dials **out** to this instance over
a WebSocket at `/api/local-connect/agent`. No inbound port, tunnel or VPN is
required on the model host, but the reverse proxy in front of GeekCubo must
forward the WebSocket upgrade (see §3 — the Nginx example includes the `map`,
and Caddy needs nothing extra).

```bash
# Optional overrides in .env
LOCAL_CONNECT_ENABLED=true
LOCAL_CONNECT_PUBLIC_URL=https://example.com   # your own origin; used in the install command
LOCAL_CONNECT_HEARTBEAT_SECONDS=45
LOCAL_CONNECT_ENROLLMENT_TTL_MINUTES=30
```

Set `LOCAL_CONNECT_PUBLIC_URL` to the public HTTPS origin. It is not derived
automatically: without it the generated install command and service files
contain a `https://your-geekcubo-host` placeholder that you must replace by
hand. The connector accepts only `https://` (or `wss://`) unless you point it
at loopback for local testing.

Operational notes:

- **Single process only.** The connection hub is in memory, matching the
  single-worker `scripts/start.py` default. Multiple Uvicorn workers or
  replicas are not supported: a chat could be routed to a worker that does not
  hold the machine's connection, and Auto's conversation state is per process
  as well. `REDIS_URL` does not change this.
- **Restarts drop connectors.** They reconnect automatically with backoff
  (capped at 30 s), but requests Auto-routed to a local model fail while a
  machine is offline unless the policy allows cloud fallback.
- **Run the connector on the model host.** `pip install .` from a checkout, then
  `geekcubo-connector enroll` and `geekcubo-connector run`. The published image
  also ships the `geekcubo_connector` package, so a colocated model host can run
  `docker compose exec api python -m geekcubo_connector run` instead.
- **No tool calls over the connector.** Text streams in both directions, and
  image parts reach Ollama models that Ollama reports as vision-capable (other
  adapters receive them unchanged). Tool calls are not carried back, so local
  models are advertised without Tools and Auto never sends tool requests to
  them.
- **Credentials** are hashed server-side (SHA-256, like the enrollment code
  path) and written `0600` on the model host. Rotate or revoke from
  **Local AI Connect → machine → Rotate / Revoke**; revoking closes the live
  socket on the next frame.

Firewall: the model host needs outbound TCP 443 to the GeekCubo origin only.

### Upgrading an existing install (do not lose data)

The data volume (`geekcubo-data`) and database file (`geekcubo.db`) live
under `/data`. Back them up before upgrading — see §5. Confirm which volume
Compose mounts for this project, especially if you run Compose from a different
directory than the original install:

```bash
docker inspect geekcubo --format '{{.Name}}: {{range .Mounts}}{{.Name}} -> {{.Destination}} {{end}}' 2>/dev/null
docker compose stop api
docker compose cp api:/data ./pre-update-backup
docker compose build api
docker compose up -d api
```

Compose names the volume `<project>_geekcubo-data`, where `<project>` defaults
to the directory name. If you upgrade from a **different directory**, Compose
may create a new, empty volume. Pin the existing one using the exact name
printed above, for example:

```yaml
volumes:
  geekcubo-data:
    external: true
    name: geekcubo-main_geekcubo-data
```

Then `docker compose up -d` reuses the existing data volume.

## 3. Nginx reverse proxy

```nginx
# /etc/nginx/sites-available/example.com   (use your own hostname)

# Required for the Local AI Connect agent WebSocket
# (/api/local-connect/agent). The variable name is deliberately unique so it
# cannot collide with a $connection_upgrade map defined elsewhere. Without this
# map nginx -t fails with "unknown variable".
map $http_upgrade $geekcubo_connection_upgrade {
    default upgrade;
    ''      close;
}

server {
    listen 80;
    server_name example.com;   # or api.example.com — your hostname
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name example.com;   # or api.example.com — your hostname

    ssl_certificate     /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;

    # Streaming responses (SSE) must not be buffered.
    proxy_buffering off;
    proxy_read_timeout 3600s;
    proxy_send_timeout 3600s;
    # Chat attachments default to 25 MB per file (ATTACHMENT_MAX_MB); keep
    # this at least that large or uploads fail at the proxy with 413.
    client_max_body_size 32m;

    location / {
        proxy_pass http://127.0.0.1:8787;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade           $http_upgrade;
        proxy_set_header Connection        $geekcubo_connection_upgrade;
    }
}
```

The long `proxy_read_timeout` keeps the connector socket alive between
heartbeats and lets long SSE generations finish. Caddy's `reverse_proxy`
handles the WebSocket upgrade automatically, so no extra Caddy configuration is
needed.

```bash
ln -s /etc/nginx/sites-available/example.com /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx
```

Set `TRUST_PROXY_HEADERS=true` in `.env` and restart the container so the
session cookie is `Secure` and client IPs are logged correctly.

> Leaving the API publicly reachable is a choice, not a default. The dashboard
> requires an administrator login; inference requires an `sk-geek-*` key. If
> only your own machines need it, restrict by IP (`allow`/`deny`) or use a VPN.

## 4. First-run checklist

1. Open your dashboard address (for example `https://example.com`, or
   `http://127.0.0.1:8787` on a local install). On a fresh install `./install.sh` prints the
   one-time setup token. For a manual install, retrieve it through the local
   CLI: `docker compose exec api python -m app.admin_cli setup-token`.
2. Create the administrator account. Password minimum is 8 characters. The
   token is single-use and becomes invalid once the administrator exists.
3. Add a provider (**Providers**) or a custom OpenAI-compatible provider.
4. Register models and set the **confirmed custom price** (the only rate used
   for spend accounting). Catalog prices appear separately as reference
   estimates. Auto, Cheapest and cost ceilings use confirmed prices only, so
   a model with just a reference estimate stays out of Auto until you confirm
   its price (or explicitly enable `pricing.allow_reference_estimates`).
5. In **Manage models**, resolve any ambiguous catalog match, then confirm the
   Tools / Vision / JSON states. Unknown is a valid state and is not assumed
   supported or free. Use the row and bulk controls to enable, disable or
   remove models without disturbing discovery results.
6. Create a routing profile if you want anything other than `auto`.
7. **Connect a tool** to generate configuration for OpenCode / Claude Code.
8. Choose a routing strategy on the **Routing** page and use **Test a routing
   decision** to confirm Auto picks the model you expect.
9. Send one request and confirm it appears in **Analytics**, including its
   recorded cost source.
10. Optionally open the **Chat** tab. The composer shows the context budget for
   each turn (from the `x-geek-context-*` response headers); **Settings → Chat →
   Web search** enables citations once a backend is configured.
11. Optionally connect a model host under **Local AI** — see
    "Local AI Connect" in §2 and the WebSocket notes in §3.

## 5. Backup and restore

Everything that matters is in the data volume (database, chat attachments and
the auto-generated `.geekcubo-secrets` file) plus `.env`. Copy through the
container (`docker compose cp`), so you never have to guess the volume's
Compose-generated name.

```bash
# Backup (stopped, so the SQLite -wal/-shm files are consistent)
docker compose stop api
docker compose cp api:/data "./geekcubo-data-$(date +%F)"
cp .env "geekcubo-env-$(date +%F).bak"     # contains CREDENTIAL_ENCRYPTION_KEY
docker compose start api
tar czf "geekcubo-backup-$(date +%F).tar.gz" "./geekcubo-data-$(date +%F)"
```

The `/data` directory now also contains the auto-generated `.geekcubo-secrets`
file (see "Security and encryption" in the README). It is part of the backup,
so the `docker compose cp api:/data` step above captures it automatically.

```bash
# Restore
docker compose stop api
docker compose cp "./geekcubo-data-YYYY-MM-DD/." api:/data
docker compose start api
```

Verify the restore on a scratch host before you need it; a backup you have
never restored is a guess. `docker compose down -v` deletes the volume — never
run it on production.

If you prefer volume-level snapshots, resolve the real name first:

```bash
docker inspect geekcubo --format '{{range .Mounts}}{{if eq .Destination "/data"}}{{.Name}}{{end}}{{end}}'
```

## 6. Updating safely

```bash
docker compose stop api                     # stop writes
docker compose cp api:/data "./geekcubo-data-pre-update-$(date +%F)"
git pull
docker compose build api
docker compose up -d api
docker compose logs -f api                  # expect geekcubo_ready
```

Startup schema checks in `packages/db/migrate.py` apply the repairs required by
this release. These include adding missing columns and indexes, repairing stored
spend counters, widening a budget column on PostgreSQL, and adding model
metadata/reference-price and request cost-provenance columns. They are designed
to be repeatable, not to leave all stored values unchanged. Back up before
updating: migrations can fail, and older application versions may not support
the new schema.

Model metadata, confirmed custom prices, reference estimates and historical
cost provenance live in the database. A backup that omits `/data` loses them;
the implementation does not silently re-derive confirmed rates from a public
catalog.

### Rollback

```bash
git checkout <previous-tag>
docker compose build api
docker compose up -d api
```

Do not assume a code rollback is compatible with the newer database schema.
If the previous version does not start cleanly, stop it and use the §5 restore
procedure with the pre-update archive, then deploy the matching application
version.

## 7. Troubleshooting

| Symptom | Check |
|---|---|
| `./install.sh` cannot reach Docker | Start Docker, add your user to the `docker` group, or rerun with `sudo`. |
| `./install.sh` health check times out | `docker compose ps` and `docker compose logs --tail=100 api` — usually a bad `.env` value or a failed migration. |
| `./install.sh` cannot display a setup token | The administrator may already exist (expected) or the CLI failed; run `docker compose exec api python -m app.admin_cli status`. |
| `geekcubo` container restarts | `docker compose logs api` — usually a bad `.env` value or a failed migration. |
| 502 from Nginx | Container up? `curl http://127.0.0.1:8787/health`. |
| Logged out on every request | `TRUST_PROXY_HEADERS=true` and `X-Forwarded-Proto` set by Nginx. |
| Streams arrive all at once | `proxy_buffering off`. |
| Local AI Connect machine stays offline | Check `docker compose logs api` for `/api/local-connect/agent` rejections; confirm the proxy forwards `Upgrade`/`Connection` (Nginx `map` block) and that `LOCAL_CONNECT_PUBLIC_URL` matches the URL the connector dials. |
| Provider keys "cannot be decrypted" | `CREDENTIAL_ENCRYPTION_KEY` changed. Restore it, or set `CREDENTIAL_ENCRYPTION_PREVIOUS_KEY` to the old value and restart. |
| Costs show $0 | The model has no configured price. Set it on the model, then check **Model data → Price lookup**; unknown cost is labelled, never assumed free. |
| A profile returns 422 `profile_restriction` | Its provider/model allowlist or price ceiling excluded every candidate. Widen it. |

Logs are rotated by the `logging:` block in `docker-compose.yml`
(3 × 10 MB). Application logs never include API keys or prompt contents;
provider keys are redacted.

## 8. Security posture

- Administrator sessions: HttpOnly + SameSite cookie, CSRF token, Argon2id
  password hashing, 8-character minimum, login rate limiting.
- Inference keys (`sk-geek-*`) can only call inference endpoints — never the
  dashboard or configuration APIs.
- Provider credentials are encrypted at rest with `CREDENTIAL_ENCRYPTION_KEY`.
- Metadata source fetching is SSRF-guarded (https, pinned DNS, redirect
  re-validation, size/time caps, no provider keys).
- The container runs as an unprivileged user and binds to loopback.
