## Зачем существует GeekCubo

Автоматическая маршрутизация моделей должна давать разработчикам контроль, а не неопределённость.

GeekCubo появился из практической проблемы: при использовании собственных ключей провайдеров ИИ не всегда очевидно, какой провайдер обработает запрос, может ли fallback задействовать отдельно оплачиваемый сервис и почему была выбрана конкретная модель.

Мы хотели самостоятельно размещаемую альтернативу, в которой политики маршрутизации, допустимые провайдеры, возможности моделей, ценовые допущения и поведение fallback видимы и настраиваемы.

GeekCubo построен на этом принципе: **ваши ключи, ваша инфраструктура, ваши решения о маршрутизации.**

Нет обязательного размещённого кошелька маршрутизации. Вы сами настраиваете провайдеров и модели, доступные маршрутизатору, и можете посмотреть, как автоматическая маршрутизация принимает решения.

### Открытое происхождение

GeekCubo основан на [OrcaRouter Lite](https://github.com/Continuum-AI-Corp/OrcaRouter-Lite) — проекте с открытым исходным кодом под лицензией MIT. Мы благодарны его первоначальным разработчикам за основу, на которой вырос GeekCubo.

GeekCubo разрабатывается и поддерживается независимо, со своими функциями, архитектурой и направлением развития. Он не связан с первоначальными разработчиками OrcaRouter и не одобрен ими.

Сведения об авторстве и лицензии — в разделе [Лицензия](#лицензия).

## Быстрый старт за 60 секунд

Запустите GeekCubo на своей машине; принесите свои ключи провайдеров.

```bash
git clone https://github.com/GeekCubo/GeekCubo-AI-Router.git
cd GeekCubo-AI-Router
./install.sh
```

Скрипт проверяет Docker и Compose, валидирует конфигурацию, выполняет `docker compose up -d --build`, ждёт настоящий эндпоинт `/health` и при новой установке показывает одноразовый токен настройки администратора. Повторный запуск безопасен: том данных, `.env`, учётная запись администратора, ключи провайдеров, секреты шифрования и API-ключи сохраняются.

Ручная установка (та же конфигурация Compose):

```bash
cp .env.example .env
docker compose up -d --build
docker compose exec api python -m app.admin_cli setup-token   # только пока администратор не создан
```

Базовый URL: `http://127.0.0.1:8787/v1`. Используйте ключ `sk-geek-*`, созданный в панели. Токен настройки одноразовый, становится недействительным после создания администратора и требует обращения как с паролем. Порт привязан только к loopback; для удалённого доступа используйте SSH-туннель или TLS-обратный прокси.

На VPS укажите в `.env` параметр `PUBLIC_BASE_URL` со своим адресом — корневым доменом вроде `https://example.com` или поддоменом вроде `https://api.example.com`, оба варианта равноценны. GeekCubo полностью работает на вашей инфраструктуре и не зависит от серверов, которыми управляет GeekCubo; см. [DEPLOYMENT.md](./DEPLOYMENT.md).

## `model="auto"` — главная фича

Отправьте `model="auto"`: GeekCubo отбирает из допущенных к Auto моделей те, что могут обслужить запрос, ранжирует их выбранной в **Routing** стратегией и вызывает лучшую, с ограниченной цепочкой fallback. Никаких ручных правил маршрутизации и кода оптимизации затрат в вашем приложении.

```python
client.chat.completions.create(
    model="auto",
    messages=[{"role": "user", "content": [
        {"type": "text", "text": "What's in this image?"},
        {"type": "image_url", "image_url": {"url": "data:..."}},
    ]}],
)
# → рассматриваются только модели с возможностью Vision «Поддерживается»;
#   порядок задаёт активная стратегия
```

Выбранная модель возвращается вызывающему через заголовок ответа `x-geek-resolved-model`, чтобы вы могли логировать/показывать, что фактически использовалось.

### Какие модели может использовать Auto

Каждый запрос Auto фильтруется в таком порядке; модель, не прошедшая шаг, никогда не выбирается — даже как fallback:

1. **Допущена** — встроенный провайдер с рабочим ключом или включённый пользовательский провайдер с отметкой *Включить в Auto*; сама модель включена.
2. **Подтверждённая цена** — прайсовая цена или заданная вами. Неизвестная цена никогда не считается бесплатной; справочная оценка учитывается, только если вы это разрешили.
3. **Подходит по возможностям** — каждая нужная возможность (Tools, Vision, JSON-режим, JSON Schema) имеет статус **Поддерживается**. «Неизвестно» никогда не удовлетворяет требованию.
4. **Помещается** — оценка промпта укладывается в известное окно контекста. Неизвестное окно модель не исключает.
5. **Разрешена** — allowlist ключа API и, при наличии, ограничения профиля маршрутизации.

### Стратегии

| Стратегия | Как ранжирует оставшихся кандидатов | Если данных нет |
|---|---|---|
| **Balanced** (по умолчанию) | Равный вес оценки качества и смешанной цены; порог качества сначала отсекает слабые модели. Участвуют только модели с оценкой. | Без оценок: сортировка по цене с пометкой в заметках маршрутизации. |
| **Cheapest** | Минимальная смешанная цена (30 % вход, 70 % выход); при равенстве — по id модели. | Все цены неизвестны: кандидатов нет, вместо угадывания — диагностика. |
| **Quality First** | Максимальная оценка качества; ручные оценки заменяют Artificial Analysis. | Без оценок: цена как заменитель (сначала самая дорогая), с пометкой. |
| **Adaptive** | Наблюдаемая доля успешных ответов, затем задержка по вашему журналу запросов (7 дней). | Меньше 20 запросов на модель: ведёт себя как Balanced и сообщает об этом. |
| **Adaptive-Gated** | Относит запрос к *Mundane* или *Hard* (инструменты, изображения, длинные промпты, много сообщений, большой `max_tokens`) и ранжирует только этот пул. | В пуле нет подходящей модели: пул *Fallback*, затем *Mundane* для сложных запросов, если разрешено; никогда — весь каталог. |
| **Fastest** (устаревшая) | Измеренная пропускная способность и время до первого токена; модели без замеров исключаются. | Без замеров: сортировка по цене с пометкой. |

**Использовать Auto:** отправьте `model="auto"` или выберите **Авто (выбирает роутер)** в чате. **Конкретная модель:** отправьте её полный id или выберите в чате. **Сменить стратегию:** нажмите карточку на странице Routing (сохраняется сразу). **Исключить модель из Auto:** отключите модель, выберите *Исключить из Auto* у провайдера или удалите подтверждённую цену. **Почему эта модель?** **Проверка решения маршрутизации**, заголовки `x-geek-routing-*` или Analytics. **Нет подходящей модели:** ответ 422 объясняет причину. Маршрутизация *моделей* Auto не связана с зарезервированным режимом Auto веб-поиска.

На странице Routing в дашборде доступна вся политика Auto: **Fallback, эскалация и непрерывность** (число попыток fallback, режим и пороги эскалации, целевой пул, режим shadow, stickiness) и **Проверка решения маршрутизации** — dry-run, показывающий выбранную модель, tier, стратегию и каждый этап фильтрации, отбросивший кандидатов. Провайдеру ничего не отправляется.

## Нативный чат: веб-поиск и бюджет контекста

Вкладка **Chat** на дашборде обрезает историю переписки до контекстного окна
выбранной модели. Каждый ответ сообщает оценку токенов, бюджет и число
пропущенных старых сообщений, поэтому укороченный ответ никогда не принимается
за сбой модели.

Веб-поиск необязателен и по умолчанию выключен. Настройте его в **Настройки →
Чат → Веб-поиск** с SearXNG (собственный хостинг), Brave или Tavily. SearXNG
запускается через `./install.sh` или `docker compose --profile search up -d`.
Ключи поиска хранятся зашифрованными отдельно от ключей инференса, а ссылки на
источники показываются только для страниц, которые бэкенд действительно вернул.
Режим `auto` зарезервирован и пока не реализован.

## Нативный чат: вложения

Композер принимает файлы тремя способами: скрепка, перетаскивание на диалог и
вставка. Вставленное изображение становится вложением; вставленный обычный
текст обрабатывается как раньше.

| Тип | Форматы | Что видит модель |
|---|---|---|
| `image` | PNG, JPEG, WebP, GIF, BMP, TIFF | Передаётся частями изображения модели со зрением |
| `document` | PDF, DOCX, RTF | Извлечённый текст с разделителями |
| `spreadsheet` | XLSX, XLS, ODS, CSV, TSV | Текст по листам, с ограничением |
| `text` / `code` | TXT, MD, JSON, YAML, исходники | Необработанный текст с разделителями |
| `archive` | ZIP, tar, gzip | Список записей и чтение с ограничением; никогда не распаковывается на диск |
| `video` / `audio` | MP4, WebM, MOV, MP3, WAV, … | Видео: метаданные и равномерно взятые кадры. Аудио: только метаданные |

Текстовые вложения всегда превращаются в блок с разделителями в сообщении
пользователя, который прочитает любая модель. Изображения становятся настоящими
частями изображения только для текущего хода; в более старой истории они
сворачиваются в маркер `[attached: name]`, чтобы не искажать окно контекста.
Если закреплена модель без зрения, отправка отклоняется с диагностикой
`no_vision`, а не отбрасывает файл молча.

Ограничения на сервере (настраиваются переменными: `ATTACHMENTS_ENABLED`,
`ATTACHMENT_MAX_MB`, `ATTACHMENT_DIR`; см. `.env.example`):

- До 8 вложений на сообщение.
- 25 МБ на файл по умолчанию, с жёстким потолком.
- Непривязанные загрузки удаляются через 24 часа.

Ошибки извлечения показываются по каждому файлу и никогда не блокируют
введённый текст. `GET /api/chat/attachments/limits` сообщает браузеру, что можно
загружать, чтобы интерфейс применял те же правила до отправки.

Для кадров видео нужны `ffmpeg`/`ffprobe` в `PATH`; без них видео всё равно
загружается, а модели сообщается, что его нельзя прочитать. Аудио описывается
модели только метаданными — автоматическая расшифровка намеренно отключена, и
модели никогда не сообщается, что она слышала то, чего не слышала.

## Локальный AI Connect

Подключите модели, которые уже работают на вашем оборудовании, к тому же
каталогу, тем же политикам и той же маршрутизации `model="auto"`, что и облачные
провайдеры. Коннектор — агент, который подключается только наружу: он открывает
WebSocket к вашему экземпляру GeekCubo, сообщает о доступных локальных моделях и
отвечает на запросы чата. Без входящего порта, туннеля, VPN и облачного аккаунта.

**Панель → Локальный AI Connect → Подключить машину** проводит через восемь
шагов: создать одноразовый код регистрации, запустить коннектор, одобрить машину,
включить нужные модели и убедиться, что они доступны для Auto.

```bash
# На машине с моделями (Python 3.11+), из клона этого репозитория
pip install .
geekcubo-connector enroll --server https://example.com --code lcenr-...   # your GeekCubo address
geekcubo-connector run
```

Коннектор автоматически проверяет распространённые локальные среды:

| Адаптер | Базовый URL по умолчанию | Протокол |
|---|---|---|
| `ollama` | `http://127.0.0.1:11434` | Родные `/api/tags`, `/api/show`, `/api/chat` |
| `lmstudio` | `http://127.0.0.1:1234` | OpenAI-совместимый `/v1` |
| `vllm` | `http://127.0.0.1:8000` | OpenAI-совместимый `/v1` |
| `llamacpp` | `http://127.0.0.1:8080` | OpenAI-совместимый `/v1` |
| `custom` | нет (через `--url`) | Любой OpenAI-совместимый `/v1`-сервер (`--api-key` для Bearer-токена) |

`--adapter` ограничивает набор проверяемых адаптеров, `--url adapter=URL` задаёт
нестандартный порт. `python -m geekcubo_connector ...` эквивалентно скрипту
`geekcubo-connector`. Панель предлагает готовые файлы служб systemd, launchd и
Windows, чтобы коннектор запускался вместе с машиной.

Коды регистрации одноразовые, по умолчанию истекают через 30 минут и не дают
никаких прав, пока администратор не одобрит машину. После одобрения локальные
модели появляются в каталоге как `local/<машина>/<модель>`; их можно закрепить
напрямую или включить в `model="auto"`.

Локальная маршрутизация управляется блоком `local` политики маршрутизации:

- `enabled` — разрешить одобренные локальные модели в Auto.
- `no_cloud_fallback` — если Auto выбрал локальную модель, а машина офлайн,
  запрос завершается ошибкой, а не повторяется в облаке молча.
- `machines` — ограничить Auto конкретными id машин; пусто — все одобренные и
  пригодные для авто-маршрутизации.

Локальная модель имеет подтверждённую нулевую цену (работает на вашем оборудовании), поэтому всегда проходит ценовой фильтр Auto и стоит первой в **Cheapest**. Исключить её из Auto можно переключателем Auto у машины или блоком `local`. Что путь поддерживает сейчас: обнаружение моделей, потоковый текст и автоматическое переподключение (backoff до 30 с) у всех адаптеров; изображения — для моделей, которые Ollama помечает как поддерживающие зрение (другие адаптеры получают их без изменений). **Вызовы инструментов через коннектор не возвращаются**, поэтому локальные модели публикуются без Tools, и Auto не отправляет им запросы с инструментами.

Настройки (все необязательные, см. `.env.example`):

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `LOCAL_CONNECT_ENABLED` | `true` | Главный переключатель; `false` закрывает endpoint агента и скрывает локальные модели. |
| `LOCAL_CONNECT_PUBLIC_URL` | пусто | Публичный URL для команды установки и файлов служб; если пусто — подставляется `https://your-geekcubo-host`. |
| `LOCAL_CONNECT_HEARTBEAT_SECONDS` | `45` | Как часто подключённая машина отмечается (обновляет время последней активности). |
| `LOCAL_CONNECT_ENROLLMENT_TTL_MINUTES` | `30` | Срок жизни кода регистрации. |

Сокет агента — WebSocket на `/api/local-connect/agent`, поэтому любой обратный
прокси перед GeekCubo должен передавать заголовок `Upgrade`. Сгенерированный
`./install.sh` конфиг Nginx уже содержит нужный `map`, а Caddy обрабатывает
WebSocket сам. Хаб соединений в памяти рассчитан на **один процесс** сервера;
перезапуск обрывает коннекторы до их переподключения (с задержкой до 30 с).
Учётные данные машины — bearer-секреты: на сервере хранятся в виде хеша, на
хосте модели записываются с правами `0600`, отзываются и ротируются из панели. Несколько воркеров или реплик не поддерживаются; `REDIS_URL` этого не меняет.

## Стриминг

OpenAI-совместимый SSE-формат со стандартным `data: ... \n\n`-фреймингом и завершающим маркером `[DONE]` — drop-in для любого SDK, который уже стримит из OpenAI.

```python
for chunk in client.chat.completions.create(
    model="auto",
    messages=[{"role": "user", "content": "Tell me a story"}],
    stream=True,
):
    print(chunk.choices[0].delta.content or "", end="", flush=True)
```

## Нативные протокольные эндпоинты (Anthropic + Gemini)

GeekCubo говорит на трёх входящих протоколах поверх одного пайплайна маршрутизации. Клиенты, которые говорят только на wire-форматах Anthropic или Gemini, подключаются напрямую — OpenAI SDK не требуется:

```bash
# Claude Code, направленный на GeekCubo (без суффикса /v1 в базовом URL)
export ANTHROPIC_BASE_URL=http://127.0.0.1:8787
export ANTHROPIC_API_KEY=sk-geek-...
claude
```

`ANTHROPIC_AUTH_TOKEN` (отправляется как `Authorization: Bearer`) тоже работает; GeekCubo принимает оба заголовка.

```python
# google-genai SDK, направленный на GeekCubo
from google import genai
from google.genai.types import HttpOptions
client = genai.Client(api_key="sk-geek-...",
                      http_options=HttpOptions(base_url="http://127.0.0.1:8787"))
client.models.generate_content(model="auto", contents="Hello!")
```

Запросы транслируются на входе в тот же внутренний пайплайн, поэтому `model="auto"`, кросс-провайдерный кэш промптов (общий для всех протоколов), стратегии маршрутизации и аналитический дашборд работают одинаково. Гайды: [integrations/claude-code.md](./integrations/claude-code.md), [integrations/gemini-sdk.md](./integrations/gemini-sdk.md).

## Каталог моделей

Встроенный каталог (несколько сотен чат-моделей поддерживаемых провайдеров) загружается при запуске из копии [общедоступной базы цен](https://github.com/BerriAI/litellm/blob/main/model_prices_and_context_window.json), поставляемой с LiteLLM, — список моделей не нужно вести вручную. Каждая запись содержит:

- `id` (например, `gpt-4o`, `claude-3-5-sonnet-latest`)
- `provider` (мапится на ваши настроенные ключи)
- Capability-флаги: `supports_tools`, `supports_vision`, `supports_json_mode`, `supports_json_schema`
- Стоимость на токен входа/выхода (питает виджет экономии + `model="auto"`)

`GET /v1/models` возвращает `auto`, включённые профили маршрутизации и полный каталог в формате OpenAI (в формате Anthropic при заголовке `anthropic-version`).

Для моделей пользовательских провайдеров Tools, Vision, режим JSON, JSON-схема, контекст и справочные цены определяются автоматически, по каждому полю отдельно, из LiteLLM, Models.dev и Portkey при **Fetch → Select → Add Selected Models**, а источник каждого поля показывается. Значение становится «поддерживается/не поддерживается» только при надёжном совпадении с явным значением; иначе остаётся «неизвестно», и неизвестная цена не блокирует возможности. Неоднозначные модели не получают чужих значений, пока вы не выберете ключ каталога в списке с поиском. Переопределения администратора (включая «неизвестно») сохраняются при обновлениях; «Использовать каталог» снимает их. Auto, Chat и профили используют одни и те же сохранённые возможности. Режим JSON (json_object) и JSON Schema / структурированные выводы (json_schema) — независимые возможности, определяемые по отдельности; данные каталога о структурированных выводах относятся только к JSON Schema и никогда не считаются доказательством режима JSON.

## Деплой в другом месте

GeekCubo — это один Docker-контейнер. Без Compose соберите образ из checkout и храните данные в именованном томе:

```bash
docker build -t geekcubo .
docker run -d --name geekcubo -p 127.0.0.1:8787:8000 \
  -v geekcubo-data:/data \
  -e DATABASE_URL=sqlite+aiosqlite:////data/geekcubo.db \
  geekcubo
```

Релизы с тегами настроены на публикацию мультиархитектурного образа в `ghcr.io/geekcubo/geekcubo-ai-router` (`.github/workflows/release.yml`); используйте это имя после выхода релиза. VPS и обратный прокси: [DEPLOYMENT.md](./DEPLOYMENT.md).

## Что в коробке

- `POST /v1/chat/completions` — proxy + стриминг + `model="auto"` + кросс-провайдерный кэш промптов
- `POST /v1/messages` — **ingress для Anthropic Messages API** (Claude Code / Anthropic SDK подключаются напрямую; `+ /count_tokens`)
- `POST /v1beta/models/{model}:generateContent` — **ingress для Gemini API** (google-genai SDK подключается напрямую; `+ :streamGenerateContent`, `GET /v1beta/models`)
- `GET  /v1/models` — `auto`, профили маршрутизации и каталог моделей (встроенный из `litellm.model_cost`, плюс пользовательские и локальные модели)
- `GET/PUT/DELETE /v1/providers/{provider}` — установка / список / отзыв зашифрованных ключей провайдеров
- `GET/PUT /v1/routing` — стратегия (`balanced` / `cheapest` / `quality` / `adaptive` / `adaptive_gated`; устаревшая `fastest`) и политика; `/v1/routing-profiles` — именованные профили Auto
- `GET  /v1/analytics/{recent,routing,spend,latency,savings,baseline-comparison}` — локальная аналитика, никакая телеметрия не уходит из коробки
- `GET/POST/DELETE /v1/keys/...` — список / ротация / отзыв API-ключей
- `/api/local-connect/*` — **Локальный AI Connect**: коды регистрации, одобрение/отзыв/ротация машин, переключение моделей, генерация файлов служб и исходящий WebSocket агента на `/api/local-connect/agent` (идентификаторы маршрутизации `local/<machine>/<model>`; локальный вывод только текст)
- `POST /api/chat/attachments` — загрузка/извлечение/удаление вложений чата; `GET /api/chat/attachments/limits` сообщает серверные лимиты, чтобы UI их соблюдал
- Single-page-дашборд по `/`
- Встроенная вкладка **Chat** на дашборде — общайтесь с развёрнутыми моделями прямо в браузере; запросы маршрутизируются, кешируются и тарифицируются так же, как трафик SDK (история хранится только в локальной базе, с настраиваемым сроком хранения; обрезка контекста показывается на каждом ходу, а необязательный веб-поиск (SearXNG, Brave или Tavily) добавляет ссылки на источники)
- SQLite по умолчанию; Postgres опционально через `DATABASE_URL`; Redis опционально
- Работает как **один серверный процесс**. `REDIS_URL` переносит кэш промптов в Redis, но не делает общими для процессов Local AI Connect, состояние диалогов Auto и данные Adaptive; несколько воркеров не поддерживаются.

### Виджет экономии

`GET /v1/analytics/savings?baseline=gpt-4o&days=7` показывает, сколько ваш трафик стоил бы на эталонной модели против фактической стоимости (по прайсовой цене эталона). Запросы с неизвестной ценой не считаются экономией.
