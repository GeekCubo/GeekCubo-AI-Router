## GeekCubo क्यों मौजूद है

स्वचालित मॉडल रूटिंग से डेवलपर्स को अनिश्चितता नहीं, नियंत्रण मिलना चाहिए।

GeekCubo एक व्यावहारिक समस्या से शुरू हुआ: अपनी AI प्रोवाइडर कुंजियाँ इस्तेमाल करते समय भी हमेशा साफ़ नहीं होता कि कौन-सा प्रोवाइडर अनुरोध संभालेगा, क्या कोई फ़ॉलबैक अलग से बिल की जाने वाली सेवा इस्तेमाल कर सकता है, या कोई ख़ास मॉडल क्यों चुना गया।

हम एक सेल्फ़-होस्टेड विकल्प चाहते थे जिसमें रूटिंग नीतियाँ, योग्य प्रोवाइडर, मॉडल क्षमताएँ, मूल्य संबंधी मान्यताएँ और फ़ॉलबैक व्यवहार दिखाई दें और कॉन्फ़िगर किए जा सकें।

GeekCubo इसी सिद्धांत पर बना है: **आपकी कुंजियाँ, आपका इन्फ्रास्ट्रक्चर, आपके रूटिंग निर्णय।**

कोई अनिवार्य होस्टेड रूटिंग वॉलेट नहीं है। राउटर के लिए उपलब्ध प्रोवाइडर और मॉडल आप ख़ुद कॉन्फ़िगर करते हैं, और देख सकते हैं कि स्वचालित रूटिंग अपने निर्णय कैसे लेती है।

### ओपन-सोर्स उत्पत्ति

GeekCubo [OrcaRouter Lite](https://github.com/Continuum-AI-Corp/OrcaRouter-Lite) पर आधारित है, जो MIT लाइसेंस के तहत जारी एक ओपन-सोर्स प्रोजेक्ट है। हम इसके मूल डेवलपर्स के आभारी हैं जिन्होंने वह आधार दिया जिस पर GeekCubo विकसित हुआ।

GeekCubo स्वतंत्र रूप से विकसित और बनाए रखा जाता है, अपनी विशेषताओं, आर्किटेक्चर और उत्पाद दिशा के साथ। यह मूल OrcaRouter डेवलपर्स से संबद्ध नहीं है और न ही उनके द्वारा समर्थित है।

श्रेय और लाइसेंस विवरण के लिए [लाइसेंस](#लाइसेंस) देखें।

## 60-सेकंड क्विकस्टार्ट

GeekCubo को अपनी मशीन पर चलाएँ; अपनी provider कुंजियाँ साथ लाएँ।

```bash
git clone https://github.com/GeekCubo/GeekCubo-AI-Router.git
cd GeekCubo-AI-Router
./install.sh
```

स्क्रिप्ट Docker और Compose की जाँच करती है, कॉन्फ़िगरेशन सत्यापित करती है, `docker compose up -d --build` चलाती है, वास्तविक `/health` एंडपॉइंट की प्रतीक्षा करती है, और नई इंस्टॉल पर व्यवस्थापक का एक-बार उपयोग होने वाला सेटअप टोकन दिखाती है। इसे दोबारा चलाना सुरक्षित है: डेटा वॉल्यूम, `.env`, व्यवस्थापक खाता, provider क्रेडेंशियल, एन्क्रिप्शन सीक्रेट और API कुंजियाँ सुरक्षित रहती हैं।

मैन्युअल इंस्टॉल (वही Compose कॉन्फ़िगरेशन):

```bash
cp .env.example .env
docker compose up -d --build
docker compose exec api python -m app.admin_cli setup-token   # केवल तब तक जब व्यवस्थापक मौजूद न हो
```

बेस URL: `http://127.0.0.1:8787/v1`। डैशबोर्ड में बनाई गई `sk-geek-*` कुंजी का उपयोग करें। सेटअप टोकन केवल एक बार मान्य है, व्यवस्थापक बनने के बाद अमान्य हो जाता है, और इसे पासवर्ड की तरह संभालें। पोर्ट केवल loopback पर खुला है; दूरस्थ पहुँच के लिए SSH टनल या TLS रिवर्स प्रॉक्सी का उपयोग करें।

VPS पर `.env` में `PUBLIC_BASE_URL` को अपने पते पर सेट करें — `https://example.com` जैसा रूट डोमेन या `https://api.example.com` जैसा सबडोमेन, दोनों बराबर विकल्प हैं। GeekCubo पूरी तरह आपके इन्फ्रास्ट्रक्चर पर चलता है और GeekCubo द्वारा संचालित किसी होस्ट पर निर्भर नहीं है; [DEPLOYMENT.md](./DEPLOYMENT.md) देखें।

## `model="auto"` — मुख्य फ़ीचर

`model="auto"` भेजें, और GeekCubo Auto के योग्य मॉडलों को उन तक सीमित करता है जो अनुरोध पूरा कर सकते हैं, उन्हें **Routing** में चुनी गई रणनीति से क्रमबद्ध करता है और सबसे अच्छे को कॉल करता है, पीछे एक सीमित फ़ॉलबैक श्रृंखला के साथ। न मैनुअल रूटिंग नियम, न आपके ऐप्लिकेशन में लागत अनुकूलन कोड।

```python
client.chat.completions.create(
    model="auto",
    messages=[{"role": "user", "content": [
        {"type": "text", "text": "What's in this image?"},
        {"type": "image_url", "image_url": {"url": "data:..."}},
    ]}],
)
# → केवल वे मॉडल विचार में आते हैं जिनकी Vision क्षमता «समर्थित» है;
#   सक्रिय रणनीति क्रम तय करती है
```

समाधान किया गया मॉडल `x-geek-resolved-model` रिस्पॉन्स हेडर के माध्यम से कॉलर को वापस उजागर किया जाता है, ताकि आप लॉग/प्रदर्शित कर सकें कि वास्तव में क्या उपयोग हुआ।

### Auto कौन-से मॉडल इस्तेमाल कर सकता है

हर Auto अनुरोध इस क्रम में उम्मीदवार छाँटता है; किसी भी चरण में विफल मॉडल कभी नहीं चुना जाता, फ़ॉलबैक के रूप में भी नहीं:

1. **योग्य** — काम करती कुंजी वाला अंतर्निहित प्रोवाइडर, या सक्षम और *Auto में शामिल* कस्टम प्रोवाइडर; मॉडल स्वयं सक्षम हो।
2. **पुष्ट मूल्य** — सूची मूल्य या आपके द्वारा सेट मूल्य। अज्ञात मूल्य कभी मुफ़्त नहीं माना जाता; संदर्भ अनुमान तभी गिना जाता है जब आप अनुमति दें।
3. **सक्षम** — अनुरोध की हर ज़रूरी क्षमता (Tools, Vision, JSON मोड, JSON Schema) **समर्थित** हो। «अज्ञात» कोई आवश्यकता पूरी नहीं करता।
4. **संदर्भ में फ़िट** — अनुमानित प्रॉम्प्ट ज्ञात कॉन्टेक्स्ट विंडो में आ जाए। अज्ञात विंडो वाला मॉडल इस कारण बाहर नहीं होता।
5. **अनुमत** — API कुंजी की अनुमति-सूची और, यदि हो, रूटिंग प्रोफ़ाइल की सीमाएँ।

### रणनीतियाँ

| रणनीति | बचे उम्मीदवारों का क्रम | डेटा न होने पर |
|---|---|---|
| **Balanced** (डिफ़ॉल्ट) | गुणवत्ता स्कोर और मिश्रित मूल्य को बराबर भार; गुणवत्ता न्यूनतम सीमा कमज़ोर मॉडल पहले हटाती है। केवल स्कोर वाले मॉडल भाग लेते हैं। | स्कोर न हों तो मूल्य से क्रम, रूटिंग नोट्स में उल्लेख के साथ। |
| **Cheapest** | सबसे कम मिश्रित मूल्य (30 % इनपुट, 70 % आउटपुट); बराबरी पर मॉडल id से। | सभी मूल्य अज्ञात: कोई उम्मीदवार नहीं, अनुमान के बजाय निदान। |
| **Quality First** | सबसे ऊँचा गुणवत्ता स्कोर; मैनुअल स्कोर Artificial Analysis से ऊपर। | स्कोर न हों तो मूल्य को विकल्प (सबसे महँगा पहले), उल्लेख के साथ। |
| **Adaptive** | आपके अपने अनुरोध लॉग (7 दिन) में देखी गई सफलता दर, फिर विलंबता से पुनः क्रम। | प्रति मॉडल 20 से कम अनुरोध: Balanced की तरह चलता है और यह बताता है। |
| **Adaptive-Gated** | अनुरोध को *Mundane* या *Hard* (टूल, चित्र, लंबे प्रॉम्प्ट, कई संदेश, बड़ा `max_tokens`) में बाँटकर केवल उसी पूल में क्रम। | पूल में सक्षम मॉडल न हो: *Fallback* पूल, फिर अनुमति हो तो कठिन अनुरोधों के लिए *Mundane*; कभी पूरा कैटलॉग नहीं। |
| **Fastest** (पुराना) | बेंचमार्क थ्रूपुट और पहले टोकन का समय; माप रहित मॉडल बाहर। | माप न हों तो मूल्य से क्रम, उल्लेख के साथ। |

**Auto इस्तेमाल करें:** `model="auto"` भेजें या चैट में **ऑटो (राउटर चुनता है)** चुनें। **कोई ख़ास मॉडल:** उसकी पूरी id भेजें या चैट में चुनें। **रणनीति बदलें:** Routing पेज पर रणनीति कार्ड क्लिक करें (तुरंत सहेजा जाता है)। **मॉडल को Auto से बाहर रखें:** मॉडल अक्षम करें, प्रोवाइडर पर *Auto से बाहर करें* चुनें या पुष्ट मूल्य हटाएँ। **यह मॉडल क्यों?** **रूटिंग निर्णय का परीक्षण**, `x-geek-routing-*` हेडर या Analytics। **कोई योग्य मॉडल नहीं:** अनुमान के बजाय कारण सहित 422। Auto *मॉडल* रूटिंग का आरक्षित वेब-सर्च ऑटो मोड से कोई संबंध नहीं है।

डैशबोर्ड में Routing पेज पूरी Auto नीति दिखाता है: **Fallback, escalation और continuity** (fallback प्रयास, escalation मोड और सीमाएँ, लक्ष्य pool, shadow मोड, stickiness) और **रूटिंग निर्णय का परीक्षण**, एक dry-run जो चुना गया मॉडल, tier, रणनीति और हर वह फ़िल्टर चरण दिखाता है जिसने उम्मीदवार हटाए। कुछ भी प्रोवाइडर को नहीं भेजा जाता।

## नेटिव चैट: वेब सर्च और कॉन्टेक्स्ट बजट

डैशबोर्ड का **चैट** टैब बातचीत का इतिहास चुने गए मॉडल की कॉन्टेक्स्ट विंडो तक
सीमित करता है। हर उत्तर अनुमानित टोकन, बजट और छोड़े गए पुराने संदेशों की संख्या
बताता है, इसलिए छोटा किया गया उत्तर कभी मॉडल की विफलता नहीं समझा जाता।

वेब सर्च वैकल्पिक है और डिफ़ॉल्ट रूप से बंद है। इसे **सेटिंग्स → चैट → वेब
सर्च** में SearXNG (स्व-होस्टेड), Brave या Tavily के साथ कॉन्फ़िगर करें।
SearXNG को `./install.sh` या `docker compose --profile search up -d` से शुरू
किया जा सकता है। सर्च कुंजियाँ एन्क्रिप्टेड रूप में, इन्फ़रेंस कुंजियों से अलग
संग्रहित होती हैं, और साइटेशन केवल उन्हीं पेजों के लिए दिखते हैं जो बैकएंड ने
वास्तव में लौटाए। `auto` सर्च मोड आरक्षित है और अभी लागू नहीं हुआ है।

## नेटिव चैट: अनुलग्नक

कंपोज़र तीन तरह से फ़ाइलें स्वीकार करता है: पेपरक्लिप, बातचीत पर ड्रैग-एंड-ड्रॉप, और
पेस्ट। पेस्ट की गई छवि अनुलग्नक बन जाती है; पेस्ट किया गया सादा टेक्स्ट पहले जैसा
रहता है।

| प्रकार | फ़ॉर्मैट | मॉडल क्या देखता है |
|---|---|---|
| `image` | PNG, JPEG, WebP, GIF, BMP, TIFF | दृष्टि-सक्षम मॉडल को छवि भागों के रूप में भेजी जाती है |
| `document` | PDF, DOCX, RTF | निकाला गया टेक्स्ट, सीमांकित |
| `spreadsheet` | XLSX, XLS, ODS, CSV, TSV | शीट-दर-शीट टेक्स्ट, सीमित |
| `text` / `code` | TXT, MD, JSON, YAML, स्रोत फ़ाइलें | कच्चा टेक्स्ट, सीमांकित |
| `archive` | ZIP, tar, gzip | प्रविष्टियों की सूची और सीमित पठन; डिस्क पर कभी नहीं खोला जाता |
| `video` / `audio` | MP4, WebM, MOV, MP3, WAV, … | वीडियो: मेटाडेटा और समान अंतराल के फ़्रेम। ऑडियो: केवल मेटाडेटा |

टेक्स्ट अनुलग्नक हमेशा उपयोगकर्ता संदेश में सीमांकित ब्लॉक बनते हैं, जिन्हें कोई भी
मॉडल पढ़ सकता है। छवियाँ केवल वर्तमान टर्न के लिए वास्तविक छवि भाग बनती हैं; पुराने
इतिहास में वे `[attached: name]` मार्कर में सिमट जाती हैं ताकि कॉन्टेक्स्ट विंडो
गलत न दिखे। यदि आप ऐसा मॉडल पिन करते हैं जो छवियाँ नहीं ले सकता, तो फ़ाइल चुपचाप
छोड़ने के बजाय `no_vision` निदान के साथ भेजना अस्वीकार कर दिया जाता है।

सर्वर-साइड सीमाएँ (पर्यावरण चर से समायोज्य: `ATTACHMENTS_ENABLED`,
`ATTACHMENT_MAX_MB`, `ATTACHMENT_DIR`; `.env.example` देखें):

- प्रति संदेश अधिकतम 8 अनुलग्नक।
- डिफ़ॉल्ट रूप से प्रति फ़ाइल 25 MB, कठोर सीमा तक सीमित।
- संदेश से न जुड़े अपलोड 24 घंटे बाद हटा दिए जाते हैं।

निष्कर्षण विफलताएँ प्रति फ़ाइल दिखाई जाती हैं और आपके लिखे टेक्स्ट को कभी नहीं
रोकतीं। `GET /api/chat/attachments/limits` ब्राउज़र को बताता है कि क्या अपलोड किया
जा सकता है, ताकि UI भेजने से पहले वही नियम लागू करे।

वीडियो फ़्रेम के लिए `PATH` में `ffmpeg`/`ffprobe` आवश्यक हैं; इनके बिना वीडियो फिर
भी अपलोड होता है और मॉडल को बताया जाता है कि इसे पढ़ा नहीं जा सकता। ऑडियो मॉडल को
केवल मेटाडेटा के रूप में बताया जाता है — स्वचालित प्रतिलेखन जानबूझकर अक्षम है, और
मॉडल को कभी नहीं कहा जाता कि उसने कुछ सुना जो उसने नहीं सुना।

## स्थानीय AI कनेक्ट

अपने ही हार्डवेयर पर चल रहे मॉडलों को उसी कैटलॉग, उन्हीं नीतियों और उसी
`model="auto"` रूटिंग में लाएँ जो आपके क्लाउड प्रदाताओं के लिए हैं। कनेक्टर केवल
बाहर की ओर जुड़ने वाला एजेंट है: यह WebSocket से आपके GeekCubo इंस्टेंस को डायल
करता है, जो स्थानीय मॉडल दिखते हैं उन्हें घोषित करता है और चैट अनुरोधों का उत्तर
देता है। बीच में कोई इनबाउंड पोर्ट, टनल, VPN या क्लाउड खाता नहीं।

**डैशबोर्ड → स्थानीय AI कनेक्ट → एक मशीन जोड़ें** आठ चरणों में मार्गदर्शन करता है:
एकबारगी नामांकन कोड बनाएँ, कनेक्टर चलाएँ, मशीन स्वीकृत करें, चाहे गए मॉडल सक्षम
करें और पुष्टि करें कि वे Auto के लिए उपलब्ध हैं।

```bash
# जिन मशीनों पर मॉडल चलते हैं (Python 3.11+), इस रिपॉज़िटरी के चेकआउट से
pip install .
geekcubo-connector enroll --server https://example.com --code lcenr-...   # your GeekCubo address
geekcubo-connector run
```

कनेक्टर सामान्य स्थानीय रनटाइम अपने आप खोजता है:

| एडाप्टर | डिफ़ॉल्ट बेस URL | प्रोटोकॉल |
|---|---|---|
| `ollama` | `http://127.0.0.1:11434` | मूल `/api/tags`, `/api/show`, `/api/chat` |
| `lmstudio` | `http://127.0.0.1:1234` | OpenAI-संगत `/v1` |
| `vllm` | `http://127.0.0.1:8000` | OpenAI-संगत `/v1` |
| `llamacpp` | `http://127.0.0.1:8080` | OpenAI-संगत `/v1` |
| `custom` | कोई नहीं (`--url` से दें) | कोई भी OpenAI-संगत `/v1` सर्वर (Bearer टोकन के लिए `--api-key`) |

`--adapter` से खोज सीमित करें और `--url adapter=URL` से एडाप्टर को गैर-डिफ़ॉल्ट
पोर्ट पर भेजें। `python -m geekcubo_connector ...` इस `geekcubo-connector` स्क्रिप्ट
के बराबर है। डैशबोर्ड तैयार systemd, launchd और Windows सेवा फ़ाइलें देता है ताकि
कनेक्टर मशीन के साथ फिर से शुरू हो।

नामांकन कोड एकबारगी होते हैं, डिफ़ॉल्ट रूप से 30 मिनट में समाप्त होते हैं, और जब
तक कोई प्रशासक मशीन स्वीकृत नहीं करता तब तक कुछ भी प्रदान नहीं करते। स्वीकृति के
बाद स्थानीय मॉडल कैटलॉग में `local/<machine>/<model>` के रूप में दिखते हैं और सीधे
पिन किए जा सकते हैं या `model="auto"` में शामिल किए जा सकते हैं।

स्थानीय मार्ग `local` रूटिंग-नीति ब्लॉक से नियंत्रित होता है:

- `enabled` — स्वीकृत स्थानीय मॉडलों को Auto में शामिल करें।
- `no_cloud_fallback` — जब Auto स्थानीय मॉडल चुने और वह मशीन ऑफ़लाइन हो, तो चुपचाप
  क्लाउड पर पुनः प्रयास करने के बजाय अनुरोध विफल करें।
- `machines` — Auto को विशिष्ट मशीन आईडी तक सीमित करें; खाली = सभी स्वीकृत और
  ऑटो-योग्य मशीनें।

स्थानीय मॉडल की कीमत पुष्ट शून्य है (आपके हार्डवेयर पर चलता है), इसलिए यह हमेशा Auto की मूल्य जाँच पास करता है और **Cheapest** में सबसे आगे रहता है। मशीन के Auto स्विच या `local` ब्लॉक से इसे Auto से बाहर रखें। यह पथ आज क्या समर्थन करता है: सभी एडाप्टरों के लिए मॉडल खोज, स्ट्रीमिंग टेक्स्ट और स्वचालित पुनः कनेक्शन (30 सेकंड तक बैकऑफ़); उन मॉडलों के लिए चित्र इनपुट जिन्हें Ollama विज़न-सक्षम बताता है (अन्य एडाप्टरों को वे बिना बदले मिलते हैं)। **टूल कॉल कनेक्टर के ज़रिए वापस नहीं आते**, इसलिए स्थानीय मॉडल Tools के बिना प्रकाशित होते हैं और Auto उन्हें टूल वाले अनुरोध नहीं भेजता।

कॉन्फ़िगरेशन (सभी वैकल्पिक, `.env.example` देखें):

| वेरिएबल | डिफ़ॉल्ट | उद्देश्य |
|---|---|---|
| `LOCAL_CONNECT_ENABLED` | `true` | मास्टर स्विच; `false` एजेंट एंडपॉइंट बंद करता है और स्थानीय मॉडल छिपाता है। |
| `LOCAL_CONNECT_PUBLIC_URL` | खाली | इंस्टॉल कमांड और सेवा फ़ाइलों में लिखा जाने वाला सार्वजनिक URL; खाली होने पर `https://your-geekcubo-host` प्लेसहोल्डर। |
| `LOCAL_CONNECT_HEARTBEAT_SECONDS` | `45` | कनेक्टेड मशीन कितनी बार रिपोर्ट करती है (आख़िरी बार देखे जाने का समय अपडेट होता है)। |
| `LOCAL_CONNECT_ENROLLMENT_TTL_MINUTES` | `30` | नामांकन कोड का जीवनकाल। |

एजेंट सॉकेट `/api/local-connect/agent` पर एक WebSocket है, इसलिए GeekCubo के आगे
का कोई भी रिवर्स प्रॉक्सी HTTP `Upgrade` हेडर अग्रेषित करना चाहिए। `./install.sh`
द्वारा बनाया गया Nginx कॉन्फ़िगरेशन आवश्यक `map` शामिल करता है और Caddy WebSocket
स्वयं संभालता है। इन-मेमोरी कनेक्शन हब **एकल सर्वर प्रोसेस** मानता है; पुनः
आरंभ होने पर कनेक्टर टूट जाते हैं जब तक वे फिर से न जुड़ें (अधिकतम 30 सेकंड के
बैकऑफ़ के साथ)। मशीन क्रेडेंशियल बियरर रहस्य हैं: सर्वर पर हैश में संग्रहीत,
मॉडल होस्ट पर `0600` अनुमतियों के साथ लिखे जाते हैं, और डैशबोर्ड से कभी भी
रद्द या रोटेट किए जा सकते हैं। कई वर्कर या रेप्लिका समर्थित नहीं हैं; `REDIS_URL` इसे नहीं बदलता।

## स्ट्रीमिंग

मानक `data: ... \n\n` फ्रेमिंग और टर्मिनल `[DONE]` सेन्टिनल के साथ OpenAI-compatible SSE फ़ॉर्मेट — किसी भी SDK के लिए drop-in जो पहले से OpenAI से स्ट्रीम करता है।

```python
for chunk in client.chat.completions.create(
    model="auto",
    messages=[{"role": "user", "content": "Tell me a story"}],
    stream=True,
):
    print(chunk.choices[0].delta.content or "", end="", flush=True)
```

## नेटिव प्रोटोकॉल एंडपॉइंट (Anthropic + Gemini)

GeekCubo एक ही रूटिंग पाइपलाइन पर तीन इनबाउंड प्रोटोकॉल बोलता है। जो क्लाइंट केवल Anthropic या Gemini wire फ़ॉर्मेट बोलते हैं, वे सीधे कनेक्ट होते हैं — किसी OpenAI SDK की आवश्यकता नहीं:

```bash
# Claude Code, GeekCubo पर पॉइंट किया गया (बेस URL में /v1 सफ़िक्स नहीं)
export ANTHROPIC_BASE_URL=http://127.0.0.1:8787
export ANTHROPIC_API_KEY=sk-geek-...
claude
```

`ANTHROPIC_AUTH_TOKEN` (`Authorization: Bearer` के रूप में भेजा जाता है) भी काम करता है; GeekCubo दोनों हेडर स्वीकार करता है।

```python
# google-genai SDK, GeekCubo पर पॉइंट किया गया
from google import genai
from google.genai.types import HttpOptions
client = genai.Client(api_key="sk-geek-...",
                      http_options=HttpOptions(base_url="http://127.0.0.1:8787"))
client.models.generate_content(model="auto", contents="Hello!")
```

Requests को एज पर उसी आंतरिक पाइपलाइन में अनुवादित किया जाता है, इसलिए `model="auto"`, cross-provider प्रॉम्प्ट कैश (सभी प्रोटोकॉल में साझा), रूटिंग रणनीतियाँ और analytics डैशबोर्ड सभी एक जैसे काम करते हैं। गाइड: [integrations/claude-code.md](./integrations/claude-code.md), [integrations/gemini-sdk.md](./integrations/gemini-sdk.md)।

## मॉडल कैटलॉग

अंतर्निहित कैटलॉग (समर्थित प्रोवाइडरों के कई सौ चैट मॉडल) स्टार्टअप पर LiteLLM के साथ आने वाली [समुदाय-संचालित मूल्य डेटाबेस](https://github.com/BerriAI/litellm/blob/main/model_prices_and_context_window.json) की प्रति से लोड होता है — कोई मॉडल सूची मैन्युअली बनाए रखने की ज़रूरत नहीं। प्रत्येक प्रविष्टि में शामिल है:

- `id` (जैसे `gpt-4o`, `claude-3-5-sonnet-latest`)
- `provider` (आपकी कॉन्फ़िगर की गई कुंजियों पर मैप)
- क्षमता फ्लैग्स: `supports_tools`, `supports_vision`, `supports_json_mode`, `supports_json_schema`
- प्रति-टोकन इनपुट/आउटपुट लागत (बचत विजेट + `model="auto"` को चलाती है)

`GET /v1/models` OpenAI प्रारूप में `auto`, सक्षम रूटिंग प्रोफ़ाइल और पूरा कैटलॉग लौटाता है (`anthropic-version` हेडर होने पर Anthropic प्रारूप में)।

कस्टम प्रदाता मॉडलों के लिए Tools, Vision, JSON mode, JSON Schema, कॉन्टेक्स्ट और संदर्भ कीमतें **Fetch → Select → Add Selected Models** पर LiteLLM, Models.dev और Portkey से अपने-आप, हर फ़ील्ड अलग से, तय होती हैं और हर फ़ील्ड का स्रोत दिखाया जाता है। कोई मान केवल विश्वसनीय और स्पष्ट मिलान पर ही समर्थित/असमर्थित होता है, अन्यथा अज्ञात रहता है; अज्ञात कीमत क्षमताओं को नहीं रोकती। अस्पष्ट मॉडलों को तब तक कोई उधार मान नहीं मिलता जब तक आप खोज-योग्य सूची से कैटलॉग कुंजी न चुनें। प्रशासक ओवरराइड ("अज्ञात" सहित) रीफ़्रेश के बाद भी बने रहते हैं; "कैटलॉग उपयोग करें" उन्हें हटाता है। Auto, Chat और प्रोफ़ाइल एक ही सहेजी गई क्षमताओं का उपयोग करते हैं। JSON मोड (json_object) और JSON Schema / संरचित आउटपुट (json_schema) दो स्वतंत्र क्षमताएँ हैं जो अलग-अलग हल होती हैं; कैटलॉग के संरचित-आउटपुट साक्ष्य केवल JSON Schema के लिए गिने जाते हैं, कभी भी JSON मोड के लिए नहीं।

## कहीं और डिप्लॉय करें

GeekCubo एक ही Docker कंटेनर है। Compose के बिना, चेकआउट से इमेज बनाएँ और डेटा एक नामित वॉल्यूम पर रखें:

```bash
docker build -t geekcubo .
docker run -d --name geekcubo -p 127.0.0.1:8787:8000 \
  -v geekcubo-data:/data \
  -e DATABASE_URL=sqlite+aiosqlite:////data/geekcubo.db \
  geekcubo
```

टैग किए गए रिलीज़ `ghcr.io/geekcubo/geekcubo-ai-router` पर मल्टी-आर्किटेक्चर इमेज प्रकाशित करने के लिए सेट हैं (`.github/workflows/release.yml`); रिलीज़ प्रकाशित होने के बाद यह नाम इस्तेमाल करें। VPS और रिवर्स प्रॉक्सी: [DEPLOYMENT.md](./DEPLOYMENT.md)।

## बॉक्स में क्या है

- `POST /v1/chat/completions` — proxy + स्ट्रीमिंग + `model="auto"` + cross-provider प्रॉम्प्ट कैश
- `POST /v1/messages` — **Anthropic Messages API इनग्रेस** (Claude Code / Anthropic SDK सीधे कनेक्ट होते हैं; `+ /count_tokens`)
- `POST /v1beta/models/{model}:generateContent` — **Gemini API इनग्रेस** (google-genai SDK सीधे कनेक्ट होता है; `+ :streamGenerateContent`, `GET /v1beta/models`)
- `GET  /v1/models` — `auto`, रूटिंग प्रोफ़ाइल और मॉडल कैटलॉग (`litellm.model_cost` से अंतर्निहित, साथ में कस्टम और स्थानीय मॉडल)
- `GET/PUT/DELETE /v1/providers/{provider}` — एन्क्रिप्टेड provider कुंजियाँ सेट / सूचीबद्ध / रद्द करें
- `GET/PUT /v1/routing` — रणनीति (`balanced` / `cheapest` / `quality` / `adaptive` / `adaptive_gated`; पुराना `fastest`) और नीति; `/v1/routing-profiles` — नामित Auto प्रोफ़ाइल
- `GET  /v1/analytics/{recent,routing,spend,latency,savings,baseline-comparison}` — local analytics, कोई टेलीमेट्री बॉक्स से बाहर नहीं जाती
- `GET/POST/DELETE /v1/keys/...` — API कुंजियाँ सूचीबद्ध / रोटेट / रद्द करें
- `/api/local-connect/*` — **स्थानीय AI कनेक्ट**: नामांकन कोड, मशीन स्वीकृति/निरस्तीकरण/रोटेशन, मॉडल टॉगल, सेवा-फ़ाइल निर्माण, और `/api/local-connect/agent` पर आउटबाउंड एजेंट WebSocket (`local/<machine>/<model>` रूटिंग आईडी; स्थानीय अनुमान केवल टेक्स्ट)
- `POST /api/chat/attachments` — चैट अनुलग्नक अपलोड/निकालें/हटाएँ; `GET /api/chat/attachments/limits` सर्वर की लागू सीमाएँ बताता है ताकि UI उन्हीं का पालन करे
- `/` पर सिंगल-पेज डैशबोर्ड
- डैशबोर्ड में बिल्ट-इन **चैट** टैब — ब्राउज़र से डिप्लॉय किए गए मॉडलों से बात करें; requests SDK ट्रैफ़िक की तरह ही रूट, कैश और कॉस्ट-ट्रैक होती हैं (इतिहास केवल लोकल डेटाबेस में रहता है, रिटेंशन सेट किया जा सकता है; कॉन्टेक्स्ट ट्रिमिंग हर टर्न में बताई जाती है, और वैकल्पिक वेब सर्च (SearXNG, Brave या Tavily) साइटेशन जोड़ता है)
- डिफ़ॉल्ट रूप से SQLite; `DATABASE_URL` के माध्यम से Postgres opt-in; Redis वैकल्पिक
- **एक सर्वर प्रोसेस** के रूप में चलता है। `REDIS_URL` प्रॉम्प्ट कैश को Redis में ले जाता है, लेकिन Local AI Connect, Auto की बातचीत स्थिति और Adaptive डेटा प्रोसेस के बीच साझा नहीं होते; मल्टी-वर्कर समर्थित नहीं है।
